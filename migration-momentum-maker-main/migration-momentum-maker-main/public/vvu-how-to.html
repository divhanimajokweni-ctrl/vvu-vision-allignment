01 Getting Started

VVU · STUDIO runs entirely in your browser. There is nothing to install. The platform is a single-page app served from the root URL /.

How to open the platform

  1. Open the root URL in the Preview Panel (or your live deploy). The Control Plane dashboard loads at /#/dashboard.
  2. The first thing you see is the dashboard: a hero header with KPIs, the 5 Environments row, Deal of the Day, the doctrine panel, live telemetry, and the bridge status.
  3. If you're a new user, the Onboarding Wizard launches automatically (see section 03).
Tip

The platform uses hash-based routing. Every surface has a URL like /#/forge or /#/inference. You can bookmark or share any surface directly.

03 Onboarding Wizard

The 4-step wizard launches on first visit. It walks you from identity to a proven, device-bound, integrated state.

  1. Identity — Enter your founder handle. This becomes your canonical identity in the epistemic runtime.
  2. Device Bind — A real QR code is generated (scannable by any authenticator app). The TOTP URI binds your device to the platform. Scan it with Google Authenticator, Authy, or similar.
  3. Integrations — Toggle which environments you want active (Forge, Bench, Fire, Field, Press). You can change these later.
  4. Proven — The wizard mints your first proof receipt and marks you as onboarded. The full control plane unlocks.
Important

The QR code is real — generated with the qrcode library using a valid TOTP URI. You can scan it with your phone and it will produce real 6-digit codes.

To re-run the wizard later: Ctrl+K → type "onboarding" → Enter.

04 Forge Environment FORGE

A NotebookLM-style study environment. Upload sources, take notes, and build knowledge graphs that feed the epistemic runtime.

How to use Forge

  1. Open Forge — Ctrl+K → "forge", or click the FORGE card on the dashboard.
  2. Create a notebook — Click "New Notebook". Give it a title and topic.
  3. Add sources — Paste URLs, upload documents, or add text snippets. Each source becomes a citable node.
  4. Take notes — Notes auto-link to sources. The system tracks which sources back each claim.
  5. Export to Bench — Send structured findings to the Bench asset registry as evidence rows.
Epistemic tie-in

Every note in Forge can be tagged with a tier: RAW, COMPUTED, VERIFIED, or PROVEN. Only PROVEN notes can anchor a Fire (financial) action.

05 Bench Environment BENCH

An Excel/Sheets-style asset registry. Every row is a receipted asset with a node-locked license. This is where hardware meets the doctrine.

How to use Bench

  1. Open Bench — Ctrl+K → "bench".
  2. The grid shows every asset row: name, class, license key, hardware hash, status.
  3. Click any row to open the asset detail: full license audit trail, hardware fingerprint, and event log.
  4. Licensing — Navigate to /#/licensing to see the node-locked license engine. Licenses are bound by a weighted score: Motherboard (45) + CPU (30) + GUID (15) + Disk (10) = 100, threshold 85.
Weighted licensing

If a component changes (e.g. RAM upgrade), the license stays valid because the score still clears 85. If the motherboard changes, the score drops below threshold and the license must be re-issued.

06 Fire Environment FIRE

A Binance-style collective savings engine. Ubuntu Pools + ProofBridge. ZAR ledger only. This is where money moves — and it is constitutionally gated.

How to use Fire

  1. Open Fire — Ctrl+K → "fire", or Ctrl+8 for Ubuntu Pools.
  2. Browse pools — Commercial (R533k), Campus (R5k), Creator (R8k–R50k). Each pool has a goal, contributors, and a ProofBridge escrow.
  3. Contribute — Open a pool, click "Contribute", enter amount (ZAR). ProofBridge holds the funds in escrow until the pool's goal is met.
  4. Receipt — Every contribution mints a SHA-256 receipt. This is your proof of participation.
Constitutional rule (Article I §1.3)

Fire never emits PROVEN on its own. A pool can only disburse if the Epistemic Runtime has already minted a PROVEN proof for the underlying claim. vote=PASS + proof=FAIL + authorization=EXECUTE → REJECTED — enforced at machine level.

07 Field Environment FIELD

Infrastructure and asset monitoring. Edge devices stream receipted telemetry. Dual-tier storage: IndexedDB pond → S3+IPFS ocean.

How to use Field

  1. Open Field — Ctrl+K → "field".
  2. Device list — See all paired edge devices: rail-pins, cameras, strain gauges. Each shows battery, signal, last telemetry timestamp.
  3. Live telemetry — Click a device to see its real-time data stream (vibration, temperature, presence).
  4. EIS receipts — Every telemetry packet is an Evidence Inspection Statement receipt. Tamper-evident, replay-resistant.
  5. Pair a new device — Go to /#/bridges. The device presents its public key + a nonce signed by the gateway. The vault validates before admitting.

08 Press Environment PRESS

An IEEE + YouTube hybrid publishing library. Peer-grade papers alongside explainer videos.

How to use Press

  1. Open Press — Ctrl+K → "press".
  2. Three tabs — Papers (DOI-tagged), Videos (receipted uploads), Record (capture new).
  3. Read a paper — Click any paper card. The full text opens with DOI, abstract, methodology, and evidence hashes.
  4. Watch a video — Click any video card. Each video carries a receipted upload timestamp.
  5. Publish — Use the Record tab to capture a new video chunk (5-second .webm segments) or upload a paper draft.

How to use the Model Registry

  1. Open the gateway — Ctrl+K → "inference", or go to /#/inference.
  2. Enable a model — Click the toggle on any model card. The card lights up.
  3. Adjust thresholds — Each enabled model shows a threshold editor (e.g. flood_risk 0.85, intrusion_confidence 0.95, displacement 1.5mm).
  4. Run inference — Click "Run Inference". The Python gateway simulates a result, SHA-256 hashes it, and writes it to the WORM log.
  5. Read the WORM log — The log feed shows every inference: status (PROVEN / INCONCLUSIVE / BLOCKED), severity, confidence %, model class, hash, timestamp.
Epistemic humility

If satellite (DInSAR) says 2.6mm displacement but the IoT gauge says 0.1mm, the system emits INCONCLUSIVE + MANUAL_VERIFICATION_REQUIRED. It never guesses.

13 Epistemic Doctrine

The doctrine is the heart of VVU · STUDIO. It defines how claims become proofs, and how proofs authorize actions.

The tier ladder

Tier Meaning Who can emit
RAW Unverified input Any sensor or user
COMPUTED Derived from RAW via a known function The runtime
VERIFIED Checked against a second source The runtime + a corroborating oracle
PROVEN Cryptographically anchored, replayable, epoch-tagged The Epistemic Runtime only — never Fire, never a model

The 7 runtime primitives

Identity → Specification → Compiler → Evidence → Evaluation → Proof → Projection

The Projection is a pure fold: Projection_E = fold(Genesis, ProofLog, Epoch). No side effects. Historical proofs remain permanently interpretable because every epoch is versioned.

Two-Gate Execution

Every action must pass TWO gates:

  1. Epistemic gate — Is the claim verified to the required tier?
  2. Constitutional gate — Is the action authorized by the current RuleSet?

Both must pass. If either fails, the action is REJECTED.

Try it live

Ctrl+K → "epistemic" to open the runtime playground. You can submit claims, watch them evaluate, mint proofs, and replay epochs.

16 Edge of Oblivion (Game)

A deep-space survival RPG with the Edge of Tomorrow mechanic. Real black-hole physics, swarm AI, crew recruitment, and upgrade persistence across timelines.

How to play

  1. Open the game — Go to /vvu_black_hole_protocol.html (or click below).
  2. Click "INITIALIZE SEQUENCE" to start.
  3. Move — W A S D to thrust. Your ship has momentum — manage it.
  4. Aim & fire — Move mouse to aim, click to fire.
  5. Avoid the black hole — It exerts real gravity (F = G·M/r²). Cross the event horizon and you're spaghettified.
  6. Kill enemies — Yellow drones swarm and explode on contact (5 scrap each). Red pirates shoot from range (15 scrap each).
  7. Recruit crew — White flashes indicate a survivor rescue. Crew fills your manifest (max 3).
  8. Die — You wake up at Station Omega, keeping your scrap and upgrades.
  9. Buy upgrades — Reinforced Hull (50), Ion Thrusters (50), Twin-Link Cannons (100).
  10. Reboot timeline — Each death increments the timeline. Your upgrades persist. Try again, smarter.
Physics note

The black hole mass is 100,000 and sits at (0, 0, -2000). Gravity only activates within 2000 units. The event horizon is at 150 units — get closer than that and you die instantly.

The platform deploys to Vercel under the vvu-org team. Source lives on GitHub.

Custom domain (pending DNS) vvu-control.space-z.ai

How to deploy a change

  1. Commit locally — git add -A && git commit -m "feat: ..."
  2. Push to GitHub — git push origin main
  3. Vercel auto-builds — The GitHub integration triggers a production build automatically.
  4. If the build is BLOCKED (hobby plan concurrency limit) — trigger manually via the Vercel Git Push API with forceNew=1.
  5. Verify — Check the deployment is READY, then visit the production URL.
Known limitation

Vercel serverless uses ephemeral /tmp/vvu.db. Each cold instance re-creates the schema and re-seeds the 5 inference models. Writes (toggle, run inference) don't persist across instances. For persistent data, swap the Prisma datasource to Vercel Postgres.

18 Troubleshooting

The page loads but APIs return 500

This is a cold-start race: the ephemeral SQLite schema is still being created. Refresh the page. The second request hits a warm instance with the schema ready.

The Inference Gateway shows "0 MODELS"

Same cold-start issue. The 5 models auto-seed on the first GET /api/inference request. Refresh once — they'll appear.

A route shows a blank screen

Check the URL hash. It must be /#/inference (with the slash), not /#inference. The command palette always builds the correct hash.

The QR code won't scan

It's a real TOTP URI generated by the qrcode library. Make sure your authenticator app supports otpauth:// URIs (Google Authenticator, Authy, 1Password all do).

Git push fails with "Bad credentials"

Your GitHub PAT expired or was revoked (GitHub auto-revokes leaked tokens). Generate a new one at github.com/settings/tokens with repo scope.

Vercel deploy shows "Blocked"

The hobby plan allows 1 concurrent build. Delete blocked deployments via the Vercel API, then trigger a new build with forceNew=1.
